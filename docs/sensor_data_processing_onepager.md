# Sensor Data Processing

Raw wearable data were processed with the active GP pipeline. Accelerometer signals from the Empatica wrist device and McRoberts lower-back sensor were autocalibrated with a GGIR-like procedure that identifies still 10-second windows and fits the acceleration signal to local gravity, with optional temperature correction when temperature data are usable [cit]. Calibration was applied only when the estimated calibration improved the error and met the pipeline validity criterion. Non-wear was then detected before downstream feature extraction. For the Empatica wrist recordings, the default method combines charging gaps, defined as accelerometer timestamp gaps longer than 60 seconds, with DETACH-based non-wear detection on non-charging recording chunks; overlapping or closely separated non-wear intervals are merged [cit]. For the lower-back recordings, non-wear is detected with a Van Hees / GGIR-like 2013 algorithm using acceleration range and standard deviation criteria across long windows [cit].

Validity rules are domain-specific in the current repository. For lower-back gait aggregation, valid wear time is computed as recorded hours minus non-wear time, and gait amount features are averaged across days with more than 16 valid hours. The aggregation exports the number of available and valid gait days, but it does not currently exclude participants based on a minimum number of valid gait days. For wrist-derived activity and circadian features, a day is valid by default when wear time is at least 18 hours; at least three valid days are required, and at most the first seven valid days are retained. Sleep aggregation does not enforce a minimum number of valid nights in code; instead, it reports the number of valid nights for each sleep-window source so that this criterion can be applied downstream if required.

Real-world gait parameters were obtained from the lower-back McRoberts sensor after calibration, non-wear masking, and orientation-flip correction, using the `mobgap` Python library [Z]. The implemented pipeline detects gait sequences, initial contacts, laterality, cadence, stride length, walking speed, turns, and walking bouts, then applies Mobilise-D digital mobility outcome thresholds and aggregation through `MobilisedAggregator` [X, Y]. Walking-bout-level outputs include bout duration, step count, cadence, stride duration, stride length, walking speed, raw initial contacts, and turns. These outputs are summarized per day, including total walking duration, walking-bout counts, step count, and walking-speed, cadence, stride-duration, and stride-length summaries across predefined WB-duration strata. Subject-level gait aggregation then averages amount features only over valid days and averages quality features over all available gait days.

Sleep processing uses the Empatica wrist accelerometer. Sustained inactivity bouts are detected using a Van Hees 2015-style angle-z algorithm applied to 5-second epochs, with non-wear epochs masked so that sustained-inactivity bouts are interrupted by invalid data [cit]. Sleep-period windows are handled as guiders. When sleep-diary windows are available, they are processed as a diary-derived guider. In parallel, the pipeline estimates sleep period time using the HDCZA algorithm: missing and non-wear 5-second angle epochs are flagged as invalid, invalid angles are imputed from the same clock time across days, a 5-minute rolling median of absolute angle change is computed, and the longest low-movement block is retained after applying the configured block and gap rules [cit]. Lower-back time-in-bed windows can also be used as an additional guider. For each guider, the pipeline estimates sleep period time, total sleep time, wake after sleep onset, number of awakenings, sleep efficiency, sleep midpoint, longest sleep bout, and sleep fragmentation, then aggregates these metrics at subject/visit level using mean or median summaries.

Circadian rhythm metrics are derived from wrist accelerometer ENMO summarized at 1-minute resolution. Missing minutes and minutes overlapping non-wear are marked invalid; after valid-day selection, invalid values are imputed using the mean value observed at the same minute of day across retained valid days, with a zero fallback when no valid reference value exists. Non-parametric features include interdaily stability and intradaily variability, calculated on a GGIR-like hourly activity/inactivity series. The pipeline also derives L5 and M5 rest-activity summaries and fits a cosinor model to estimate MESOR, amplitude, acrophase, acrotime, and the number of valid minutes and days contributing to the model [cit].

Heart-rate processing is performed from Empatica PPG and accelerometer recordings. The BeliefPPG workflow splits recordings around accelerometer gaps longer than one second, retains sufficiently long good portions, and produces heart-rate estimates with uncertainty values [cit]. Aggregation uses selected sleep windows, filters non-positive and participant-level outlying heart-rate values, and summarizes median daytime heart rate, median nighttime heart rate, and nocturnal heart-rate dip. A separate nocturnal HRV workflow selects sleep windows with priority sleep diary, HDCZA, then lower-back time-in-bed; removes acceleration-burst periods; computes quiet PPG windows of 1-5 minutes; detects beats; applies artefact correction; and estimates window-level mean heart rate, RMSSD, SDNN, and PIP. HRV features are summarized first per night and then at participant level using median aggregation.
